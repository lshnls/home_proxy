# Аудит конфигурации развертывания Home Proxy

**Дата проверки:** 2026-04-04  
**Проверяющий:** SourceCraft Code Assistant Agent  
**Версия проекта:** текущая (git)

## Обзор проекта

Проект представляет собой набор Docker-контейнеров для организации прокси-цепи:
- **Unbound** — локальный DNS-резолвер с DNSSEC и TLS-форвардингом.
- **Tor** — клиент Tor с obfs4 мостами для обхода блокировок.
- **Privoxy** — HTTP-прокси с фильтрацией, перенаправляющий трафик в Tor.
- **Squid** — кэширующий прокси с SSL-перехватом (MITM) для прозрачного проксирования.

Дополнительно включены скрипты для управления мостами, проверки здоровья и настройки iptables.

## Результаты проверки

### 1. Docker Compose (`docker-compose.yml`)

**Статус:** ✅ В основном корректно

**Найденные проблемы:**
- Сервис Squid использует `network_mode: host`, что может привести к конфликтам портов с другими сервисами на хосте.
- Зависимости между сервисами (`depends_on`) закомментированы, что может привести к попыткам подключения к ещё не запущенным сервисам.
- Переменные окружения для портов Squid (`SQUID_PORT`, `SQUID_HTTP_PORT`, `SQUID_HTTPS_PORT`) не используются, так как порты закомментированы.

**Рекомендации:**
- Включить `depends_on` для гарантии порядка запуска (например, Tor → Privoxy → Squid).
- Рассмотреть возможность использования Docker network вместо host mode для Squid, если не требуется перехват всего трафика хоста.
- Если используется host mode, убедиться, что порты 3128, 8081, 8082 не заняты другими процессами.

### 2. Переменные окружения (`.env`)

**Статус:** ✅ Корректно

**Замечания:**
- `UNBOUND_PORT=53` — если на хосте уже работает DNS-сервер (systemd-resolved, dnsmasq), порт 53 будет занят. Это приведет к ошибке запуска контейнера.
- `TOR_CONTROL_PORT=9051` определён, но не используется в docker-compose.

**Рекомендации:**
- При конфликте порта 53 изменить `UNBOUND_PORT` на другой (например, 5353) и перенастроить клиентов.
- Добавить использование `TOR_CONTROL_PORT` в docker-compose, если планируется управление Tor через контрольный порт.

### 3. Конфигурация Tor (`torrc`, `bridges.txt`)

**Статус:** ⚠️ Требует исправления

**Найденные проблемы:**
- В `torrc` указан `ClientTransportPlugin obfs4 exec /usr/bin/lyrebird`, но в Dockerfile установлен только `obfs4proxy`. Библиотека `lyrebird` отсутствует в Alpine.
- Мосты в `bridges.txt` могут устареть (скрипт `check-and-update-tor-bridges.sh` предназначен для их обновления).

**Рекомендации:**
- Заменить строку на `ClientTransportPlugin obfs4 exec /usr/bin/obfs4proxy` (или `/usr/local/bin/obfs4proxy`).
- Регулярно запускать скрипт обновления мостов (например, через cron).
- Проверить, что `bridges_raw.txt` содержит актуальные мосты (сейчас содержит 4 моста).

### 4. Конфигурация Unbound (`unbound.conf`)

**Статус:** ✅ Корректно

**Замечания:**
- Настройки доступа (`access-control`) разрешают только локальные сети, что правильно.
- Используется TLS-форвардинг к Google DNS и Cloudflare, а для доменов `.ru` — к Yandex DNS.
- Кэширование закомментировано (`cache-min-ttl`, `prefetch`).

**Рекомендации:**
- Раскомментировать настройки кэширования для повышения производительности.
- Убедиться, что на хосте нет конфликта порта 53 (см. выше).

### 5. Конфигурация Privoxy (`config`, `user.action`)

**Статус:** ✅ Корректно

**Замечания:**
- В `config` используется `forward-socks5 / home_proxy-tor:9050 .` (имя контейнера), а в `user.action` — `tor:9050` (имя сервиса). Оба варианта могут работать, но лучше унифицировать.
- Файлы `default.action` и `match-all.action` пусты.

**Рекомендации:**
- Заменить `home_proxy-tor` на `tor` в `config` для consistency.
- Добавить базовые правила в `default.action` при необходимости.

### 6. Конфигурация Squid (`squid.conf`, `tor.list`)

**Статус:** ⚠️ Требует внимания

**Найденные проблемы:**
- `cache_peer localhost parent 8118` предполагает, что Privoxy слушает на localhost. Поскольку Privoxy публикует порт на хосте, это работает, но лучше использовать имя сервиса `privoxy:8118` (если Squid остаётся в host mode, это невозможно).
- SSL MITM требует установки самоподписанного CA сертификата (`squidCA.crt`) в доверенные хранилища клиентов.
- Файл `tor.list` содержит регулярные выражения для доменов, которые должны идти через Tor. Некоторые дублируются (например, `doubleclick.net`).

**Рекомендации:**
- Если Squid остаётся в host mode, оставить `localhost:8118`.
- Добавить инструкцию по установке CA сертификата на клиентские устройства.
- Очистить `tor.list` от дубликатов и проверить актуальность доменов.

### 7. Скрипты

#### `health-check.sh`
**Статус:** ✅ Корректно
Проверяет основные порты сервисов. Можно расширить проверкой доступности upstream (например, DNS-запрос).

#### `check-and-update-tor-bridges.sh`
**Статус:** ⚠️ Может не работать в некоторых окружениях
Использует `</dev/tcp/$ip/$port`, что требует поддержки bash. В Alpine bash может отсутствовать (по умолчанию sh). Рекомендуется использовать `nc` или `socat`.

**Рекомендации:**
- Установить `netcat-openbsd` в Docker-образ Tor или использовать `timeout` с `nc`.
- Добавить обработку ошибок.

#### `setup-iptables.sh`
**Статус:** ⚠️ Незавершенный
Переменная `SQUID_IP` не заполнена. Скрипт содержит закомментированные правила.

**Рекомендации:**
- Определить IP-адрес контейнера Squid автоматически или указать его в конфигурации.
- Протестировать скрипт в изолированном окружении перед применением на рабочей системе.

### 8. Безопасность

**Найденные проблемы:**
- Контейнеры запускаются от root (в Dockerfile нет инструкции `USER`).
- Privoxy и Unbound слушают на всех интерфейсах (`0.0.0.0`), но ограничены firewall/iptables.
- Самоподписанный CA Squid представляет риск MITM, если сертификат не защищён.

**Рекомендации:**
- Добавить непривилегированных пользователей в Dockerfile (например, `tor`, `unbound`, `privoxy`, `squid`).
- Рассмотреть использование `security_opt` и `cap_drop` в docker-compose.
- Ограничить доступ к портам Privoxy и Unbound только локальной сетью (если это не нарушает архитектуру).

## Общая оценка

Конфигурация в целом работоспособна и следует лучшим практикам для прокси-цепочки. Критические проблемы отсутствуют, но есть несколько мест, которые могут вызвать сбои в работе:

1. **Некорректный путь к obfs4proxy** в torrc — приведёт к невозможности подключения к мостам.
2. **Конфликт порта 53** — может помешать запуску Unbound.
3. **Незавершенный скрипт iptables** — может не настроить прозрачный прокси.

## План исправлений

1. **Высокий приоритет:**
   - Исправить `ClientTransportPlugin` в `torrc`.
   - Проверить и обновить мосты через скрипт.

2. **Средний приоритет:**
   - Добавить `depends_on` в docker-compose.
   - Настроить непривилегированных пользователей в контейнерах.
   - Дополнить скрипт обновления мостов проверкой через `nc`.

3. **Низкий приоритет:**
   - Оптимизировать `tor.list`, убрать дубликаты.
   - Добавить кэширование в Unbound.
   - Завершить скрипт iptables.
